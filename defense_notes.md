## Как показать работу (порядок, 5–7 минут)

1. `python manage.py test blog` → показать `OK` (58 тестов).
2. Сайт: главная → приёмы (поиск, фильтр, сортировка, страницы) → добавить приём → ошибка в форме → удалить приём (сначала подтверждение).
3. Пациент: удалить → «N қабылдау да жойылады». Врач с приёмами: удаление блокируется.
4. API в браузере `/api/appointments/`: список, потом войти (`/api-auth/login/`) и создать запись через форму внизу. Показать `409` при удалении врача с приёмами.
5. Терминал `runserver`: строки `POST ... 302` и `GET ... 200`.
6. `python manage.py shell -c "from blog import queries; queries.report()"` → таблица 101 → 1, 101 → 2, 201 → 2.
7. GitHub: показать 4 коммита и README.

## Вопросы и короткие ответы

**Что такое проект и приложение?** Проект (`config`) это настройки всего сайта, приложение (`blog`) это одна функция внутри. Приложение подключается в `INSTALLED_APPS`.

**Зачем `ForeignKey` и `ManyToManyField`?** FK это «один ко многим» (у врача много приёмов). M2M это «многие ко многим» (у приёма несколько диагнозов, и диагноз бывает у многих приёмов); Django делает для этого промежуточную таблицу.

**`PROTECT` и `CASCADE`?** `CASCADE`: удалили пациента, удалились его приёмы. `PROTECT`: врача с приёмами удалить нельзя (в вебе показываем сообщение, в API отвечаем 409).

**`makemigrations` и `migrate`?** Первая пишет файл миграции, вторая применяет его к базе.

**Что такое FBV и CBV, где у вас что?** FBV это функции, CBV это классы. Приёмы сделаны на функциях (виден каждый шаг), пациенты и врачи на классах `ListView`, `CreateView` и т.д. (меньше кода).

**GET и POST?** GET только показывает, POST меняет данные. Удаление только через POST: GET показывает страницу подтверждения.

**Что такое PRG (redirect после POST)?** После успешного сохранения сервер отвечает 302 и браузер открывает список. Если нажать F5, форма не отправится второй раз.

**Что такое CSRF и где он у вас?** Защита от поддельных форм с чужого сайта. В каждой POST-форме есть `{% csrf_token %}`, без него будет 403.

**Где валидация?** В `forms.py` (`clean_<поле>` и `clean()`), и отдельно в `serializers.py` для API. Проверка только в браузере ненадёжна, поэтому серверная есть всегда.

**Что такое N+1 и как вы его решили?** Цикл по приёмам, который на каждый приём делает запрос за врачом: 1 + 100 = 101 запрос. `select_related("doctor")` берёт врачей одним JOIN (FK). `prefetch_related("diagnoses")` берёт диагнозы вторым запросом и склеивает в Python (M2M). В API список приёмов стоит 3 запроса независимо от размера страницы; это проверено тестом `assertNumQueries(3)`.

**Почему `.order_by()` в списках с `annotate`?** После `annotate(Count(...))` Django игнорирует `Meta.ordering`, а пагинации нужен стабильный порядок.

**Что такое REST API?** Адреса, которые отдают и принимают JSON вместо HTML: GET (читать), POST (создать, 201), PUT/PATCH (изменить, 200), DELETE (удалить, 204).

**Что такое Serializer, ViewSet, Router?** Serializer переводит модель в JSON и обратно и проверяет данные. ViewSet это один класс с пятью действиями CRUD. Router сам создаёт адреса для ViewSet.

**Почему в `AppointmentSerializer` и `doctor`, и `doctor_id`?** Читаем вложенный объект врача (удобно клиенту), пишем только id (удобно при создании).

**Какие права в API?** `IsAuthenticatedOrReadOnly`: читать может любой, менять только вошедший. Без этого любой мог бы удалять данные.

**Где хранятся секреты?** `SECRET_KEY` в `.env`, файл `.env` в `.gitignore`, в репозитории только `.env.example`.

**Что тестируется?** Модели (`test_models.py`), веб-страницы (`test_crud.py`, `test_web.py`), API (`test_api.py`), включая негативные случаи (ошибка формы ничего не сохраняет, анонимный POST запрещён) и число SQL-запросов.

**Что бы улучшили?** Токенная авторизация для API, разграничение ролей (врач, регистратор), `django-filter`, Docker, PostgreSQL вместо SQLite.
